# Внешние сервисы: что нужно зарегистрировать и подключить

Сайт работает без внешних сервисов: заказы сохраняются в базе и видны в админке. Каждый сервис ниже расширяет возможности. Пока сервис не подключён, сайт честно сообщает об этом: способ оплаты не показывается покупателю, а уведомление записывается в журнал со статусом `skipped`, а не «отправлено».

| # | Сервис | Зачем | Обязательно? | Что получить | Куда указать |
|---|---|---|---|---|---|
| 1 | **Хостинг / VPS** (PS Cloud, Hoster.kz, Yandex Cloud и др.) | Работа сайта | Да | Сервер, IP | см. DEPLOYMENT.md |
| 2 | **PostgreSQL** | База данных | Да | Строка подключения | `DATABASE_URL` |
| 3 | **Регистратор домена** (mtrend.kz) | Домен, DNS | Да | Доступ к DNS | A-записи → IP сервера |
| 4 | **SSL** (Let's Encrypt, бесплатно) | HTTPS | Да | — | certbot |
| 5 | **Почта / SMTP** (Яндекс 360, Google Workspace, Unisender Go, Mailgun и др.) | Письма покупателям и уведомления о заказах | Рекомендуется | Хост, порт, логин, пароль. Записи SPF/DKIM | `SMTP_*`, email менеджеров — в админке «Настройки» |
| 6 | **Telegram Bot** (@BotFather) | Мгновенные уведомления менеджерам о новых заказах | Рекомендуется | Токен бота, ID чата или группы | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` |

| 11 | **Облачное хранилище S3** (Yandex Object Storage, PS Cloud S3, Cloudflare R2, AWS) | Хранение фото товаров, CDN | Рекомендуется (обязательно для serverless-хостинга) | Bucket, ключи доступа, публичный URL | `STORAGE_DRIVER=s3`, `S3_*` |

| 14 | **Meta Pixel** | Реклама Instagram и Facebook | По необходимости | Pixel ID | Админка → Настройки |
| 15 | **Яндекс Метрика** | Аналитика, вебвизор | По необходимости | Номер счётчика | Админка → Настройки |

## Аналитика: какие события отправляются

| Событие GA4 | Meta Pixel | Когда |
|---|---|---|
| `view_item` | `ViewContent` | Открыта карточка товара |
| `add_to_cart` | `AddToCart` | Товар добавлен в корзину |
| `begin_checkout` | `InitiateCheckout` | Открыто оформление |
| `order_created` | `OrderCreated` (custom) | Заказ оформлен **и сохранён** в базе |

Событие `purchase` с сайта **не отправляется**: на момент оформления оплата не подтверждена. Когда появится онлайн-оплата, `purchase` нужно отправлять с сервера (GA4 Measurement Protocol и Meta Conversions API) после подтверждения платежа провайдером.

## Как подключить онлайн-оплату (для разработчика)

1. Получите у банка или Kaspi документацию, тестовый стенд и ключи.
2. В `src/lib/payments.ts` установите `implemented: true` и реализуйте:
   - создание платежа (сумма берётся из `Order.total` на сервере) и редирект покупателя на платёжную страницу;
   - маршрут `src/app/api/payments/<provider>/callback/route.ts`. Он проверяет подпись провайдера и только после этого ставит `paymentStatus = PAID` и `paymentRef`;
   - идемпотентную обработку повторных уведомлений.
3. Добавьте ключи в `.env` и включите способ оплаты в админке.
