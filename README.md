# M‑TREND — интернет-магазин мужской одежды (mtrend.kz)

Полноценная e-commerce платформа для M‑TREND: каталог из базы данных, SKU-варианты (цвет × размер × ростовка) с остатками по складам, корзина, оформление заказа без регистрации, личный кабинет, админ-панель, импорт Excel/CSV и модуль обмена с 1С. Интерфейс на русском и казахском языках.

> **Тестовый режим.** После `db:seed` в базе 20 **демонстрационных** товаров (помечены «ДЕМО», `isDemo = true`). Их цены, составы, скидки и остатки условные, это не данные для продаж. Демо-товары не попадают в sitemap и закрыты от индексации, а заказы с ними помечаются как тестовые. Перед запуском удалите их: «Админка → Импорт / экспорт → Удалить демо-товары».

## Возможности

**Витрина**
- Главная страница: слайдер баннеров (управляется из админки), популярные категории, новинки, хиты продаж, костюмы, повседневный стиль, обувь, акции, готовые образы, преимущества, адреса магазинов, подписка.
- Каталог с деревом категорий (редактируется в админке). Фильтры по категории, цене, размеру, цвету, посадке (Slim/Regular), сезону, материалу, наличию, скидке и новинкам, с множественным выбором. Пять видов сортировки. На мобильных фильтры открываются в нижней шторке.
- Поиск по названию (RU/KZ), артикулу, SKU и категории.
- Карточка товара: галерея с увеличением, фото по цветам, видео, выбор цвета, размера и ростовки. Размеры без остатка нельзя выбрать. Показаны доступное количество и наличие по городам, состав, сезон, посадка, описание, таблица размеров, рекомендации по выбору, условия доставки и возврата, похожие товары. Кнопки: «В корзину», «Купить сейчас», «В избранное», «Уточнить размер» (WhatsApp с артикулом, цветом и размером).
- **Помощник подбора размера**: рост, вес, обхват груди и талии, предпочтение посадки. Расчёт идёт только по таблице замеров конкретной модели, которую загружает администратор, с учётом Slim/Regular и ростовки. Если таблицы нет, сайт честно предлагает консультацию менеджера.
- Корзина хранится в браузере и переживает перезагрузку. Цены, остатки, скидки и промокоды каждый раз пересчитываются на сервере.
- Оформление заказа в 3 шага (контакты → доставка → оплата) без регистрации. В конце — страница подтверждения с номером, составом, суммой, доставкой и статусом.
- Личный кабинет: история и статусы заказов, повтор заказа, контактные данные, адреса доставки, избранное (синхронизируется с сервером).
- Раздел «Наши магазины» (Астана, Актобе) с картами, часами работы и самовывозом.
- Полная двуязычность RU / KZ: отдельные URL `/ru/…` и `/kz/…`, hreflang, переводы интерфейса, двуязычные поля в базе.
- SEO: ЧПУ, уникальные title и description, canonical, Open Graph, JSON-LD (Product, BreadcrumbList, ClothingStore), `sitemap.xml`, `robots.txt`, noindex для фильтров, корзины, кабинета и демо-товаров.
- Аналитика: GA4, Meta Pixel и Яндекс Метрика подключаются ID в настройках. Отправляются события `view_item`, `add_to_cart`, `begin_checkout`, `order_created`. Событие оформления заказа **не** выдаётся за оплату (`purchase` не отправляется).
- Кнопка WhatsApp на всех страницах. Номер, email и ссылки на соцсети задаются в админке.

**Админ-панель `/admin`**: dashboard, заказы, товары, остатки, склады, категории, цвета, таблицы размеров, баннеры, образы, страницы, магазины, промокоды, доставка, оплата, настройки, сотрудники и роли, импорт и экспорт, интеграция с 1С, журналы. Подробнее — в разделе [Админ-панель](#админ-панель).

## Стек и архитектура

| Слой | Технология |
|---|---|
| Фреймворк | Next.js 15 (App Router, Server Components, Server Actions), React 19, TypeScript |
| Стили | Tailwind CSS 3, шрифты Inter и Cormorant Garamond (самохостинг через @fontsource, есть кириллица и казахские буквы) |
| База данных | PostgreSQL 16, Prisma ORM 6 (схема и миграции в `prisma/`) |
| Авторизация | Собственные сессии: случайный токен в httpOnly-cookie, в базе хранится только его SHA-256-хэш. Пароли хэшируются bcrypt (cost 12) |
| Файлы | Локальный диск (VPS) или любое S3-совместимое хранилище. Изображения конвертируются в WebP |
| Excel/CSV | exceljs, papaparse |
| Email | nodemailer (SMTP) |
| Тесты | Vitest (юнит-тесты бизнес-логики) |

**Модель данных** (основное, полная схема — `prisma/schema.prisma`):

```
Category (дерево) ─┐
                   ├─ Product (артикул, описание RU/KZ, посадка, сезон, материал, таблица размеров)
Color ─────────────┤     └─ ProductVariant = SKU (цвет × размер × ростовка, цена, старая цена)
SizeChart ─────────┘            └─ Stock (остаток SKU на конкретном складе)  ←  Warehouse (AST, AKT, …)
                                └─ StockMovement (журнал: заказ, отмена, возврат, ручная правка, импорт, 1С)
Order ── OrderItem (снимок товара, цены, размер, распределение по складам) ── OrderStatusHistory
PromoCode, DeliveryMethod, PaymentMethod, Store, Banner, Look, Page, Setting, Subscriber
User (CUSTOMER / MANAGER / ADMIN), Session, Address, Favorite
AuditLog, IntegrationLog, NotificationLog
```

## Быстрый запуск (локально)

Требования: **Node.js 20.9+** (рекомендуется 22 LTS), **PostgreSQL 14+**.

```bash
# 1. Зависимости
npm install

# 2. Переменные окружения
cp .env.example .env
#   заполните DATABASE_URL, SESSION_SECRET (openssl rand -hex 32), ADMIN_PASSWORD

# 3. База данных: миграции и начальные данные (справочники, магазины, демо-товары, администратор)
npx prisma migrate deploy
npm run db:seed

# 4. Запуск в режиме разработки
npm run dev
# сайт:    http://localhost:3000  (перенаправит на /ru)
# админка: http://localhost:3000/admin  (логин — ADMIN_EMAIL / ADMIN_PASSWORD из .env)
```

Production-сборка:

```bash
npm run build
npm start
```

Полезные команды:

| Команда | Что делает |
|---|---|
| `npm run dev` | Режим разработки |
| `npm run build && npm start` | Production |
| `npm run typecheck` | Проверка типов TypeScript |
| `npm test` | Юнит-тесты (подбор размера, промокоды, доставка, форматирование) |
| `npm run db:migrate` | Создать новую миграцию после изменения схемы (dev) |
| `npm run db:deploy` | Применить миграции (production) |
| `npm run db:seed` | Начальные данные (идемпотентно). `SEED_DEMO=false` — без демо-товаров |
| `npm run admin:create -- email@mtrend.kz "Имя" ADMIN` | Создать сотрудника или сбросить ему пароль (пароль из `ADMIN_PASSWORD` или сгенерируется) |
| `npm run 1c:import-file -- /path/to/exchange` | Импорт JSON-файлов обмена 1С из папки |

## Ключевые сценарии и защита данных

**Создание заказа** (`src/lib/orders.ts`, `POST /api/orders`):
1. Клиент передаёт только `variantId` и количество. Цены из браузера сервер не принимает.
2. В одной транзакции сервер заново рассчитывает цены, скидки, промокод и доставку по данным из БД.
3. Остатки списываются атомарным условным `UPDATE … WHERE quantity >= n` по складам. Сначала списывается склад магазина самовывоза, затем остальные по приоритету. Два покупателя не смогут купить последнюю единицу одновременно: проверено нагрузочным тестом, 10 параллельных заказов на 3 единицы дали ровно 3 заказа.
4. **Идемпотентность**: у каждой попытки оформления есть `idempotencyKey`. Повторная отправка формы (двойной клик, обрыв сети) вернёт тот же заказ без второго списания.
5. Если товар закончился, клиент получает актуальный расчёт, и корзина автоматически обновляется.
6. Каждое изменение остатка пишется в журнал `StockMovement`.

**Отмена и возврат** возвращают остатки на те же склады ровно один раз: флаг `stockReleased` проверяется атомарно. Переходы статусов ограничены допустимой схемой, а одновременное редактирование защищено оптимистичной блокировкой.

**Безопасность**
- Права проверяются на сервере в каждом server action и API: ADMIN — всё, MANAGER — заказы, просмотр товаров, остатки.
- Сессии хранятся только как хэш токена. Cookie `httpOnly`, `SameSite=Lax`, `Secure` в production. Сессии сотрудников живут 12 часов и сбрасываются при смене пароля или отключении.
- Лимиты запросов на вход, регистрацию, оформление заказа, подписку и API 1С. Время ответа при неверном логине выровнено.
- JSON API проверяют Origin (защита от CSRF), server actions защищены механизмом Next.js.
- Защитные заголовки (HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy). Админка закрыта от индексации.
- Чужой заказ не откроется: гость видит свой заказ только по секретной ссылке (24-байтный токен), покупатель — только свои заказы.
- Все входные данные валидируются через zod. HTML в CMS-страницах экранируется (собственный безопасный Markdown).
- Секреты хранятся только в переменных окружения и не попадают в клиентский код.
- Журнал действий сотрудников (`AuditLog`) с IP. Персональные данные покупателей в логи не пишутся.

**Оплата.** Сайт **не имитирует** онлайн-оплату. Сейчас доступны «Оплата после подтверждения менеджером» (менеджер выставляет счёт Kaspi, принимает перевод или оплату картой в магазине) и «Оплата при получении». Статус «Оплачен» менеджер ставит вручную после фактического поступления денег. Для Kaspi Pay и банковского эквайринга подготовлен реестр провайдеров (`src/lib/payments.ts`). Такой способ появится у покупателя только после реальной интеграции по договору, см. [docs/SERVICES.md](docs/SERVICES.md).

## Загрузка реального каталога

1. «Админка → Импорт / экспорт → Скачать шаблон .xlsx».
2. Заполните шаблон: одна строка — один SKU. Строки с одинаковым `article` образуют один товар. Остатки указываются в колонках `stock_AST`, `stock_AKT` (коды складов).
3. Загрузите файл с галочкой «Только проверить» и исправьте ошибки, затем загрузите без неё.
4. Новые товары создаются черновиками (если не указано `publish=1`). Добавьте фото, привяжите таблицу замеров и опубликуйте.
5. Удалите демо-товары.

Для регулярной синхронизации используйте модуль 1С: [docs/1C_INTEGRATION.md](docs/1C_INTEGRATION.md).

## Проверка работы

Сценарий каталог → выбор размера → корзина → оформление → запись в БД → обработка в админке проверен в браузере (Chromium через Playwright) на десктопе и мобильном экране:
- недоступный размер (52 у костюма 9293) нельзя выбрать;
- помощник подбора размера возвращает размер и ростовку по таблице замеров;
- промокод применяется, корзина пересчитывается сервером;
- заказ записывается в БД с распределением по складам, остатки списываются;
- в админке заказ виден, статус меняется, при отмене остатки возвращаются;
- 10 параллельных заказов на 3 единицы товара дали ровно 3 успешных заказа;
- повторная отправка с тем же ключом не создаёт дубль;
- API 1С: импорт номенклатуры и остатков, выгрузка и подтверждение заказов;
- импорт CSV с ошибочной строкой: корректные товары загружены, ошибка показана в отчёте.

Юнит-тесты: `npm test`.
